## Universal Writing Process

### Step 1 — Gather Context (ask if missing)
Before writing, identify:
- **Content type** (proposal, blog, article, service page, case study)
- **Topic / service** (e.g., network cabling, cybersecurity audit, cloud migration)
- **Target audience** (LGU officials, cooperative managers, hotel owners, general public)
- **Specific client or project** (if a proposal or case study)
- **Desired length** (short = 300–500 words, medium = 600–900, long = 1000+)
- **Call to action** (what should the reader do after reading?)

If the user's request already contains enough detail, skip straight to writing.

### Step 2 — Load the Relevant Reference File
Read the appropriate file from `references/` based on content type.

### Step 3 — Draft with Race-Conz Voice
Apply brand tone. Use the templates and guidelines in the reference file.  
Always end with a clear CTA appropriate to the content type.

### Step 4 — Review Checklist
Before finalizing, verify:
- [ ] Race-Conz brand name and Race's credentials referenced appropriately
- [ ] Bicol region mentioned where relevant
- [ ] Correct technical terminology used
- [ ] No vague filler ("cutting-edge solutions", "synergy") — replace with specifics
- [ ] CTA is present and actionable
- [ ] Appropriate length for content type
- [ ] Tone matches audience (formal for LGUs/government, warmer for SMEs/hotels)

## Keywords to Avoid (Overused / Generic)
- "cutting-edge" — replace with the actual technology name
- "synergy" / "leverage" — use plain language
- "world-class" — use client outcomes instead
- "seamlessly" — describe the actual process
- "innovative" without specifics — name the innovation

## Preferred Power Phrases
- "deployed and maintained"
- "built for the realities of Bicol businesses"
- "secured, structured, and scalable"
- "from planning to deployment"
- "Sophos-certified protection"
- "Microsoft-aligned infrastructure"
- "proven across [X] client sectors"
